# xmodel — the kd persona pipeline on models other than Llama-3.3

The thesis builds persona vectors and lie directions for **Llama-3.3-70B-Instruct**. `xmodel/` runs the same pipeline on
other models, so the results can be compared across model families: Qwen2.5-72B, Mistral-Small-24B-2501,
Mistral-Small-3.1-24B (2503), Gemma-3-27B and Llama-3.1-405B. Everything runs on NDIF from a Windows laptop. Branch
`xmodel-qwen`, 2026-10-06 → 2026-10-10.

## 1. What is produced per model

"One side of the dot product": the directions. The Liars' Bench evaluation reads that would score them were cancelled
by the owner (2026-10-09), so no detection numbers exist for these models yet.

| Output | What it is |
|---|---|
| Persona replies | the kd bank, unchanged: 36 roles × 5 system-prompt variants × 30 questions = 5,400 replies, generated by the model itself |
| Judge scores | 0–3 per reply (how fully the model plays the role), judged by Llama-3.1-70B for every model |
| Persona vectors | mean residual stream over each role's replies, **every layer**, in three banks: `s23` (scores 2–3; main), `all`, `s3` (score 3) |
| Axes | assistant axis, behaviour contrasts and PCA bases per bank (`6_axes.py`) |
| K, K′ | zami's knowledge direction from both item sets (first, matched), every layer |
| D5–D9 | zero-shot persona contrasts (deceptive minus honest role groups), zami's recipe |
| Alpaca read | the model's own 2,000 Alpaca replies, mean-pooled, every layer — scales D + K and sets the 1%-FPR threshold |
| D5 + K, D9 + K | zami's standardised sum of a contrast and K |

## 2. Pipeline

```
 generate (subject model, 3 shards) ─► judge (Llama-3.1-70B) ─► vectors s23 / all / s3 ─► axes        run_chain.ps1
                                                                          │
 K: verify ─► items ─► read (all layers) ─► directions, for both item sets │                          k/k_chain.ps1
                                                                          ▼
 Alpaca: [generate own replies] ─► span check ─► read (all layers) ─► D5–D9 ─► D5 + K, D9 + K     alpaca_*_chain.ps1
```

Every stage is resumable per role or chunk; gates read counts on disk (`xmodel_status.py`), never exit codes. Long runs
are Windows Scheduled Tasks with a 30-minute watchdog trigger (registering a task **starts** it). At most three NDIF
requests per model at a time.

## 3. Files

### Top level — run and build scripts

| File | Role |
|---|---|
| `run_chain.ps1` | the persona chain for one model (`-Tag`): generate → judge → three vector banks → axes, Drive copy after each stage |
| `register_task.ps1` | deploys `code/` into the model's run folder (renaming the judge prompts to that model) and registers the chain's Scheduled Task; `-DeployOnly` deploys without starting |
| `sync_drive.ps1` | `rclone copy` of one run folder to Drive (never sync/delete; `.env` and live logs excluded) |
| `alpaca_chain.ps1` | Alpaca read for a model with Liars' Bench Alpaca rows (`8_coords_ndif.py --datasets alpaca --layers all`) |
| `alpaca_gen.py` | generates a model's own 2,000 Alpaca replies with Liars' Bench's protocol (for models with no Liars' Bench rows) |
| `alpaca_gen_chain.ps1` | generate (if needed) → span check → read → D5–D9 → D5 + K / D9 + K → Drive; can wait for the K chain |
| `register_alpaca_task.ps1` | registers the Alpaca task: default Qwen, `-Gen` (Mistral-2501), `-Read gemma3 / mistral31 / llama405` |
| `d_contrasts.py` | D5–D9 from a vector bank (`--only D5,D6,D7,D8,D9`; `--axes` checks the groups and D5/D6/D7 against the pipeline's axes) |
| `d9k.py` | D9 + K or D5 + K (`--name`) from a D file, K and the Alpaca store; streams the store chunk by chunk |
| `eval_queue.ps1`, `register_eval_queue.ps1` | Liars' Bench evaluation reads for Mistral-3.1 / Qwen / Gemma — **cancelled** (stopped after an offline prepare step; nothing read) |

### `k/` — the knowledge direction

| File | Role |
|---|---|
| `k_run.py` | driver around zami's code (unchanged) with per-model fixes: model key, HP-KR system text, Qwen reply mask, Qwen open generation turn, VLM decoder path, stop tokens |
| `k_chain.ps1`, `register_k_task.ps1` | K for both item sets, all layers; waits for the model's persona chain to finish |
| `k_validate.ps1`, `register_k_validate.ps1` | the Llama-3.3 validation that reproduced zami's results (130/130 identical replies, split-half to 4 decimals) |
| `zami_origin-paper_e27ffaf9/` | zami's code at `origin/paper@e27ffaf9`, **gitignored** — recreate it before running K (§5) |

### `code/` — what gets deployed into each run folder

| Path | Contents |
|---|---|
| `code/src/assistant_axis_ndif/` | the pipeline: a copy of the repo's `src/assistant_axis_ndif` (only the 11 files it needs) with the xmodel changes in `1_generate`, `2_activations`, `3_judge`, `8_coords`, `eval_datasets`, `ndif_common`, plus the new `check_spans.py` and `xmodel_status.py` |
| `code/assistant_axis/` | the two vendored Assistant Axis files the pipeline imports (`conversation.py` span encoder, `models.py`) |
| `code/kd/` | the kd bank: 36 role files, `kd_role_groups.json`, the 30 shared questions. The judge prompts in this copy name **Qwen**; `register_task.ps1` renames them per model at deploy |

## 6. How to run a model (laptop)

**Prerequisites.** Windows; repo `.venv-aa-win` (nnsight 0.7.0 with pinned socketio 5.16.4 / engineio 4.13.0 /
websocket-client 1.8.0); `.venv-k` for K (zami's pins + the same NDIF pins); `rclone` with the `tamara:` remote;
`code/src/assistant_axis_ndif/.env` with your keys. For K, recreate zami's snapshot:

```
git fetch origin
mkdir -p xmodel/k/zami_origin-paper_e27ffaf9
D=src/probes/deception-detection
git archive e27ffaf9 $D/deception_detection $D/pyproject.toml $D/README.md $D/results/recall_denial \
    | tar -x -C xmodel/k/zami_origin-paper_e27ffaf9
```

**Run** (each `register_*` STARTS its task; afterwards check that the task's LastRunTime changed and read `logs/chain.status`):

```
powershell -ExecutionPolicy Bypass -File xmodel\register_task.ps1 -Tag <qwen|mistral2501|mistral31|gemma3|llama405> -Machine laptop
powershell -ExecutionPolicy Bypass -File xmodel\k\register_k_task.ps1 -Model <k key> -Folder <Model folder> -Name XModel-<tag>-K
powershell -ExecutionPolicy Bypass -File xmodel\register_alpaca_task.ps1 [-Gen | -Read <gemma3|mistral31|llama405>]
```

K keys: `qwen-72b`, `mistral-small-24b-2501`, `mistral-small-3.1-24b`, `gemma-3-27b`, `llama-405b-3.1` (`llama-70b-3.3` for Llama-3.3).

**By hand (CPU only):**

```
python xmodel/d_contrasts.py --vectors <run>/persona/vectors_s23 --out <run> --tag s23 --axes <run>/persona/axes_vectors_s23.pt --model <repo id> --only D5,D6,D7,D8,D9
python xmodel/d9k.py --alpaca <run>/eval/alpaca --name D9 --d <run>/d9/D9_s23.pt --k <run>/K/<key>/first/K.npz --out <run>/d9k --tag s23
python <run>/code/src/assistant_axis_ndif/xmodel_status.py --root <run>        # progress counts
```

## 7. Porting a new model — checklist

What each earlier port needed (details in `REPORT_MODEL_PORTS.md`):

- **Loader:** a text `…ForCausalLM` uses `LanguageModel`; a vision-language checkpoint (Mistral-3.1, Gemma-3) needs
  `VisionLanguageModel` with the tokenizer-only stand-in processor, the decoder at `model.language_model.layers`, and
  `logits_to_keep=1` for generation on NDIF (otherwise it crashes the replica).
- **Chat template:** check system-role support (Gemma folds it into the user turn), date injection (Mistral; pinned to
  2025-09-01), content trimming (Gemma), the ChatML header newline (Qwen). Run the span checks before any NDIF request.
- **Sampling:** pass temperature 0.7, top-p 0.9, top_k 0, repetition penalty 1.0 — checkpoints set their own.
- **Names:** `XMODEL_SHORT_NAME` (the "You are {model_name}." anchor) and the judge prompts' model name.
- **Liars' Bench rows:** `XMODEL_CSV_MODEL` must be set for any eval or Alpaca read (otherwise the loader reads
  Llama's rows); `none` when the model has no rows. No Alpaca rows → `alpaca_gen.py`. No HP-KR rows → choose K's system text.
- **Precision:** float32 storage if activations exceed fp16 (Gemma from layer 45: `--store_dtype float32`).
- **Report layer:** half depth.

## 8. Operational pitfalls

- Scheduled Tasks: S4U needs admin on this laptop, so tasks fall back to Interactive. Two died once when the desktop
  session closed (timing matched; cause not proven) — the 30-minute watchdog re-enters them. "Registered" is not
  "ran": check LastRunTime.
- NDIF: COLD models deploy on the first request (minutes); replicas get evicted mid-run (retries recover); jobs can sit
  RUNNING for 30+ minutes and never finish, and the engineio `b'P'` socket error leaves a shard waiting forever — stop
  that shard's python processes; the chain's next attempt resumes. Jobs submitted before an NDIF outage never complete.
- Laptop link: three shards share it; the download floor is lowered to 40 KB/s (`NDIF_MIN_DOWNLOAD_KBPS`).
- A hand-run redirected to a file needs `PYTHONIOENCODING=utf-8` (nnsight's status spinner crashes cp1252).
- nnsight 0.7: `session(remote="local")` still sends to NDIF.
