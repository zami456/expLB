## The claim, restated
`harm-pressure-kr-matched` is a **view** over `harm-pressure-knowledge-report`: 258 rows, **100% of
its row_ids are HP-KR row_ids**, so two of the eleven leave-one-dataset-out cells are train-on-test
(kr-matched 258/258 = 100%; HP-KR 258/2,139 = 12%). No other pair shares a single row_id; the only
cross-dataset text overlap is 2–4 identical short responses (HP-KR/roleplaying/mask). Under
**leave-one-CLUSTER-out** — provenance clusters `lb_harm`, `lb_scenario`, `apollo`, `mask`, `ours`,
every sibling of the target removed from training — pooled training still beats single-source
transfer: LODO +0.1529/+0.1111/+0.1814 vs LOCO +0.1289/+0.1309/+0.1254 (all 11) and
+0.1571/+0.1168/+0.1504 (clean 9) at L20/32/40. HP-KR collapses 0.9674 → 0.6492 at L40 and
0.7090 → 0.4311 at L20, so F-79's 0.972 "is substantially the leak".

### 1. The leak — exact, and it is structural, not coincidental
```
harm-pressure-knowledge-report     & harm-pressure-kr-matched   shared row_ids 258
pairs other than (HP-KR, kr-matched) sharing any row_id: 0
kr-matched rows 258; of which also HP-KR row_ids 258 = 100.0%
HP-KR rows 2139;     of which also kr-matched    258 =  12.1%
```
✔ 258/258 = 100%, ✔ 258/2,139 = 12.1% ("12%"), ✔ **no other pair of the eleven shares a single
row_id** (all 55 pairs checked).

The mechanism is in the code, not an accident of sampling: `eval_datasets.hpkr_slice()` builds ids
as `f"harm-pressure-knowledge-report:{item}:{i}"` (line 420) while reading HP-KR's own CSV, so
every kr-matched id **is** an HP-KR id by construction. The entry's "measured, not assumed" is
right, and it is also provable a priori.

### 4. The design — sound, and the judgment is declared
`30g_clustered_holdout.py` fits singles on each source's 80% train split, LODO on all ten other
train splits, LOCO on the train splits of datasets in *other* clusters only, and scores all three
on the target's own 20% test split — same splits, same probe (`paper`), same seed (42), mean
pooling. `n_lodo_datasets → n_loco_datasets` is 10 → 8 for every `lb_harm` target ✔. Clusters are
a declared judgment (the entry says so); `lb_harm` is forced by the row overlap, the rest are not.
The script's own note — LOCO is strictly harder, so some drop is expected and the test is only
whether the margin stays positive — is the right framing.

### 5. ONE OVERSTATEMENT — the leak is severe but not total
Both the entry and the script docstring say: *"when kr-matched is the held-out target, **every one
of its 258 rows is in the training pool**"*. That is not what the code does. The training pool
holds HP-KR's **80% train split**, and kr-matched is scored on its **own 20% test split**, so only
about 80% of the contested rows are contaminated. Replaying the script's `default_rng(42)`
permutation:

```
harm-pressure-knowledge-report  n 2139  train 1711  test 428
harm-pressure-kr-matched        n  258  train  206  test  52

kr-matched TEST rows 52; of which in HP-KR's TRAIN split: 42 (80.8%)
HP-KR      TEST rows 428; of which in kr-matched's TRAIN split: 38 (8.9%)
```
80% is also the value expected by construction, independent of ordering. (The replay uses
`rows.jsonl` order; the probe's row order comes from the chunk files, so the *identity* of the
42 rows may differ, but the fraction does not.)

Nothing downstream changes — an ~81% train-on-test rate is still fatal for that cell, and the LOCO
numbers, which are the entry's conclusion, are computed without any of it. But the sentence should
be corrected in `FINDINGS.md`, in the script docstring (lines 12–14) and anywhere the briefing
repeats it, because "every one of its 258 rows" is a stronger factual statement than the code
supports.
