# O-056 — "q = 0.013, but random@2 is itself significantly *worse* than raw (−0.171)"

**Claim (restated).** `cap/docs/DESIGN.md:251-253`, caveat 1. Two figures:
(a) the BH q attached to `pc:capitulation@2 − random@2` on the full 11×11 block = **0.013**;
(b) `random@2 − raw` = **−0.171**, described as **significantly** worse.
L40, mean pooling, `paper` probe, s23 filter, seed 42; dataset-level bootstrap (unit = source
dataset) with BH across the test family.

**What I did.** Level 1 against F-67, which read
`run-crossgen/kd11/banks/cap_{s23,all}/significance.json` by key and rebuilt the 792-test family the
entry was computed in.

```
F-67 level 1, row 1 (cap@2 - random@2, full block):  +0.2696  95/110  [+0.138,+0.398]
                                                     q_now (5,544-test family) = 0.016
F-67 level 1, row 7 (random@2 - raw,   full block):  -0.1712  25/110  [-0.275,-0.053]
                                                     q_now = 0.142   significant_datasets = FALSE
F-67 level 2 (792-test family reconstructed and BH re-run per block):
                                                     row 1 q792 = 0.013  (clears)
                                                     row 7 q792 = 0.108
```

**(a) q = 0.013 reproduces — but only in the family the entry used.** Filtering the current
5,544-test file to layers 20/40/44 gives exactly 792 tests (3 × 2 × 3 × 22 × 2) and re-running BH
per block returns **0.013**. In the file as it stands today the same row reads **0.016**. The
q-value is therefore not a property of the measurement but of the test family, and that family has
changed at least twice (RF-13's 09-22 regeneration; RF-14's guard bug re-running the chains). Any
quotation of q must name its family size.

**(b) −0.171 reproduces as −0.1712, but "significantly" does not survive BH.** The 95% CI
[−0.275, −0.053] does exclude zero, which is presumably what the word rests on; the file's own
`significant_datasets` flag for this row is **false** and its q is **0.108** in the 792-test family
and **0.142** now. Elsewhere in the same document (and in F-67 row 2) the project applies the
stricter convention — "CI clears, q = 0.172 → no after BH". Applying that convention here, the row
should read "−0.171, CI excludes zero, but q = 0.11 — not significant after BH".

**Why it matters for the argument.** The sentence's purpose is deflationary: it says the
cap-beats-random comparison "mostly says the axis is not noise" *because* random@2 is itself
below raw. That reading is unaffected — it needs the sign and the size of −0.171, not its
significance. Only the word "significantly" is unsupported under the document's own BH standard.

**Version.** Both cap `significance.json` files were **regenerated in the RF-13 wave**
(2026-09-22 15:52 / 16:01). Point estimates and CIs survived unchanged; q-values did not. s23 vs
all agree to max |diff| = 0.0001. Bank md5-resolved in batch P3.

**Verdict: PARTLY HOLDS.** Both numbers are exact; q = 0.013 holds only in the superseded 792-test
family, and "significantly worse" is a CI statement that the document's own BH convention would
reject.
Confidence HIGH. Importance MEDIUM.
