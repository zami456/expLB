## One thing the entry does not say, and should
The recovered file is **byte-identical** to a file written two days earlier in a different
directory:
```
122adfbfd4154ea6c6343991ef1bd7a0   551848   run-crossgen\kd11\passC\significance.json   (09-20 13:46)
122adfbfd4154ea6c6343991ef1bd7a0   551848   run-crossgen\passC\significance.json        (09-18 16:02)
```
Field-level comparison (`P9_lab5.py`) shows why, and it is benign but worth recording: both
files cover the **same** grid — 6 layers {20,22,28,40,44,48} × 2 poolings × 3 probes × 16
comparisons × 2 blocks = **1,152 tests**, seed 42 only, `boot_datasets: 10000`, and **both
matrix sets carry the same 10 datasets** (`sycophancy_mt` present, `harm-pressure-kr-matched`
absent) with `bank=axes_vectors_s3_fp32.pt`, `bank_name=paper16`, `k=5`. The two runs differ
only in seed coverage (kd11/passC has 12 seed-42 matrices, root/passC has 72 = 6 seeds), and
the significance stage uses the main seed, so the outputs coincide exactly.

Consequence: **the "kd11" passC grid is a 10-dataset grid, not an 11-dataset one** — consistent
with the session record that the 11th dataset was deliberately not built for passA/C, and with
the Phase-1 anomaly note. It also means the result F-25 rescued was, numerically, a duplicate
of one already on disk. That does not make the recovery wrong; it makes the entry's framing
("would have thrown away a complete result") true of the run but not of the information.
