# F-42 — "attn=0.75 was still too high; budget sized from heads x T^2 instead"

Batch **M1-method-claims**. Source: `kd/docs/FINDINGS.md:1151` (2026-09-20).

## The claim, restated
On the 8B rung of the scale coords extraction, halving the NDIF attention budget to 0.75 GiB
(F-41) did not stop the OOMs: **57 OOMs and 14 permanently-failed batches in the 14 minutes after
the restart**, with `harm-pressure-knowledge-report` writing 4 chunks at 17:33:55–17:34:26 and then
nothing. The known-good 70B settings do not transfer because NDIF caps memory **per process**: the
70B passB ran `--max_length 8192` with **no** `--attn_budget_gib` override (the 2.5 GiB default) and
completed. The new budgets were therefore **computed** from one row of eager attention,
`heads x T^2 x 4` bytes: 8B 32 heads → **537 MiB** at T=2048 → budget **0.55 GiB**; 3B 24 heads →
**402 MiB** → budget **0.42 GiB**; each "admits exactly one row".

### 3. The cost model is the one in the code — VERIFIED
`8_coords_ndif.py:189` — `def attn_bytes(rows, seqlen, n_heads): return rows * n_heads * seqlen *
seqlen * 4`, used by `batch_by_attention` (line 194) to bound every batch. So "sized from
heads x T^2" describes what the batcher actually does, not a post-hoc rationalisation.

### 4. The arithmetic — the DECISION is right, the UNIT LABEL is wrong
`num_attention_heads` from the cached configs: **8B = 32**, **3B = 24**, 70B = 64. Then

| rung | heads | one row at T=2048 | entry says | budget set | budget in MiB | rows admitted |
|---|---:|---:|---:|---:|---:|---:|
| 8B | 32 | 536,870,912 B = **512.00 MiB** = 536.87 MB | "537 MiB" | 0.55 GiB | 563.2 | **1** |
| 3B | 24 | 402,653,184 B = **384.00 MiB** = 402.65 MB | "402 MiB" | 0.42 GiB | 430.1 | **1** |

537 and 402 are the values in **decimal MB**, written as MiB. The same slip is in the production
script's comments (`scale/scripts/run_scale_coords.ps1:108-109`, which also writes "T=1024 -> 134
MiB / 101 MiB" where the MiB values are 128 and 96).

**It does not change the decision.** Two rows at T=2048 cost 1024 MiB (8B) and 768 MiB (3B), both
above their budgets, so "admits exactly one row" is true under either unit.

### 6. Context the log confirms
