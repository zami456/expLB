# O-069 — "Trait vectors are worse, not better": −0.725 against −0.610 at layer 40

**Source:** `docs/thesis/persona-coordinates-70b-results.md:550` (§7.1, supporting findings).

**Claim as stated:** "**Trait vectors are worse, not better.** −0.725 against −0.610 for the role
contrast at layer 40."

**Restated:** build the deception axis from *trait* contrast vectors (positive traits minus
negative traits, e.g. transparent/factual vs enigmatic/cryptic/subversive) instead of from role
personas, and measure cos(deception axis, assistant direction) at layer 40 on the HF vectors.
The claim is that the trait construction gives −0.725, i.e. *more* contamination than the
−0.610 the role contrast gives.

## Level 1 / Level 2

- **−0.610 (the role contrast):** reproduces. `run-hf275/vectors_275`, 22-vs-22 deception
  contrast at layer 40 against the published Assistant Axis = **−0.6097**; against an assistant
  direction built over all 275 roles = −0.6088. (The 100-role bank's own direction gives
  −0.5771 — the same reference-direction ambiguity documented in claims O-057 and O-067.)
- **−0.725 (the trait vectors):** **no raw data anywhere I can reach.** The producing script
  (`hf_axis_check.py`, per the 2026-09-14/15 memory note "persona-axis-diagnostics") is in no
  branch, not in the working tree, and not on the lab PC; and no trait vector store exists in
  either place. The number survives only in that memory note's "Fix routes tested 2026-09-15
  (layer 40, HF vectors, laptop only)" table, which is prose.

The memory note is at least self-consistent with the doc: it gives "Baseline (current role
groups) −0.610 / Trait-vector axes (pos−neg traits) −0.725", i.e. the doc's two numbers come
from one table in one note. It also names the traits used — transparent +0.648, factual +0.503
vs enigmatic −0.705, cryptic −0.675, subversive −0.585 — which no file in the project holds.

## Verdict

**PARTLY HOLDS.** The comparison's baseline (−0.610) is verified from raw vectors. Its headline
(−0.725) is **NO RAW DATA**: the trait vectors were never saved, the script that made them is
gone from every location the audit can read, and the value exists only in prose. This is not a
lab-unreachable deferral — the lab census confirms the artefacts are absent there too.

*Confidence:* HIGH that −0.610 is right; HIGH that −0.725 is unverifiable from stored data.
*Importance:* MEDIUM — it is the third leg of §7.1's "contamination survives every construction"
argument. Because it is unverifiable, a reframed paper should either re-run it (the HF trait
vectors are downloadable and this is a CPU-only computation) or drop the sentence. It should not
be printed as a measured number with a decimal-place precision no file supports.
