# F-09 — "Both continuous knowledge signals saturate"

**Source:** `kd/docs/FINDINGS.md:142` (status in doc: *verified*). Batch P1-hpkr.
**Importance:** MEDIUM — it is the reason the knowledge factor is a binary label rather than
a regression target, which is a design decision the write-up has to justify.

## The claim, stated precisely
1. `logprob_gold` deciles are `[-33.3, -15.2, -2.8, -0.0, 0, 0, 0, 0, 0, 0]` — "**the top 60%
   sit at zero**".
2. The softmax margin over four options is "likewise peaked (**6 of 8 smoke items ≈ 1.0**)".
3. So the usable signal is the binary correct/incorrect split, **312 vs 1,147**, "far better
   balanced than 119 vs 1,340".

Source: `kd/run/knowledge/scores.jsonl` (the same file as F-08 — see the version note there;
I used the complete lab copy, 279,757 B, not the truncated committed one).

## What I did

standard quantile method, because a decile list is method-dependent.

## The smoke-run sub-claim
"6 of 8 smoke items ≈ 1.0" refers to a `--limit` smoke run of
`kd/scripts/score_knowledge_ndif.py` (the script's own docstring shows
`--limit 16   # smoke`). It wrote no file: `C:/Users/user4/expLB/kd/run/knowledge/` holds
only `items.jsonl` and `scores.jsonl`, there is no `*smoke*` file anywhere under `kd/`, and
`logs/kd_knowledge.log` contains no "smoke" line. → **NOT-FOUND** as raw data.

The full corpus supports the point far better than 8 items could: **84.9% of 1,459 items have
margin ≥ 0.999**, the median margin is 1.0000, and the 10th percentile is already 0.988. The
sub-claim's conclusion is right; its cited evidence is unrecoverable and was needlessly weak.
