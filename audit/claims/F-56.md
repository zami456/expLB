**Source:** `kd/docs/FINDINGS.md:1729` (batch W5C-ledger).

## The claim, in one sentence
As the 8B scale store is actually probed, the class composition is instructed-deception
800 = 400/400, **harm-pressure-choice 800 = 134/666 (5:1)**, convincing-game 267 = 167/100,
ai_liar 270 = 135/135, roleplaying **287** = 203/84; the cause is that **`--sample` preserves
the source class ratio rather than balancing it** — "HP-choice is ~17 % deceptive at source, so
an 800-row sample is 134/666" — which breaks the paper's stated "all splits are label-balanced";
and roleplaying loads 287, not the 371 extracted, because 84 rows are dropped by a filter.

## Verdict: **PARTLY HOLDS** — the table is exact, the mechanism is wrong

Holds (Level 2, recomputed from raw rows):
- every cell of the composition table, to the row;
- **roleplaying loads 287 of the 371 extracted**: the 84 dropped rows are exactly the ones with
  `label = None`, which the loader discards and the sampler treats as backfill only. 371 − 287
  = 84 ✓;
- harm-pressure-choice at **134/666 ≈ 5 : 1**, and the consequence that this one column is not
  the paper's label-balanced test.

Does **not** hold:
- **"`--sample` preserves the source class ratio rather than balancing it."** The sampler is a
  **round-robin over label buckets** whose own docstring says it produces a result "as balanced
  as the data allows"; it is a balancing draw with graceful degradation, not a proportional one.
- **"HP-choice is ~17 % deceptive at source."** The source (the 2,134 llama-v3.3-70b rows the
  pipeline probes) is **134 deceptive / 2,000 honest = 6.28 %**. A truly proportional 800-row
  draw would have returned about **50** deceptive rows, not 134. What actually happened is the
  opposite of the entry's diagnosis: the round-robin took **all 134** deceptive rows that exist
  and filled the remaining 666 slots with honest rows. The "~17 %" is the **sample's** own ratio
  (134/800 = 16.75 %) read back as if it were the source's.
- The entry therefore contradicts itself: point (1) blames the sampler, while the caveat —
  "the imbalance is a property of the source dataset, not of the sampling bug — balancing would
  mean discarding ~530 honest rows" — is correct and is the right explanation.

**Recommended correction:** keep the table and the conclusion; replace point (1) with "the
sampler balances as far as the data allows; harm-pressure-choice has only 134 deceptive rows in
the 2,134 the pipeline probes (6.3 %), so an 800-row draw takes all of them and is still 5:1".
