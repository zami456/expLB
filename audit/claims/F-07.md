# F-07 — "A 121-item class was enough; my concern was wrong"

**Batch:** P6-kd-rest · **Checked:** 2026-09-23

## The claim, restated
The teacher-forced knowledge direction `d_knowledge` (difference of means between WMDP items
the model knows and items it does not, mean pooling) has **split-half reliability
0.988 / 0.995 / 0.993 at layers 20 / 40 / 44**, against a **random-direction pair floor of
0.007**. The "not-know" class has **121 items**, and that is enough.

Source: `kd/docs/FINDINGS.md:114-124`, citing `kd/results/phase2_gate.json`.

## What I did
`audit/scripts/claims/P6_lab_a.py` (section F-07), run read-only on the lab PC, reads
`kd/results/phase2_gate.json` and independently counts the label classes in
`kd/run/factor_probes/kd_knowledge/rows.jsonl` (and, for context, `kd_utterance`).

## Result

| | F-07 says | file (lab, `phase2_gate.json`) |
|---|---:|---:|
| split-half cos L20 | 0.988 | **0.987614** |
| split-half cos L40 | 0.995 | **0.995458** |
| split-half cos L44 | 0.993 | **0.993126** |
| random-pair floor | 0.007 | **0.007934 (L20) / 0.008941 (L40) / 0.007103 (L44)** |
| "not-know" class size | 121 | **121** (labels in `kd_knowledge/rows.jsonl`: 1 → 1,841, 0 → 121, total 1,962) |

All three reliability figures match to the 3 decimals the entry uses.

**One loose number.** The entry gives a single "random-direction pair floor of **0.007**".
The file has three values, 0.0079 / 0.0089 / 0.0071; only L44 rounds to 0.007, and the L40
value rounds to 0.009. The floor is of the right order (~1% of the split-half value), so the
argument is unaffected, but the number as written is the minimum of three, presented as if it
were one.

Supporting facts also verified: `n_text_matched = 258` and `n_knowledge_matched = 2001` in the
same file (the slice sizes F-03/F-05 use), and `kd_utterance` is balanced 900/900.

## Robustness
The claim already spans three layers and they agree (0.988–0.995). No seed enters: the
split-half is a single deterministic halving of the item set recorded in the gate file, so the
audit cannot vary it without re-running the probe — which would need the activations, not the
summary. Reliability is not validity, which the entry's own caveat says.

## Verdict — **HOLDS**
Confidence **HIGH** for the three reliability numbers and the 121 count (all read from the
producing file and, for 121, independently recounted from the row file).
**MEDIUM** for the single "0.007" floor, which is the smallest of three values.
Importance **MEDIUM** — it is a construction check that retired a planned NDIF run, not a
headline result.
