# F-04 — "Almost nothing clears a dataset-level bootstrap"

**Batch:** P6-kd-rest · **Checked:** 2026-09-23

## The claim, restated
In the kd11 crossgen run (paper16 bank `axes_vectors_s3_fp32.pt`, k=5, 10,000 dataset
bootstraps), **384** dataset-level significance tests were run and **1** of them is significant
after Benjamini–Hochberg correction. At **layer 40 / mean pooling / `paper` probe**:
`axes − raw` = **+0.015** with a dataset-level 95% CI of **[−0.170, +0.187]** and **q = 0.931**;
`axes − datapca` = **+0.026** with **q = 0.855**.

Source: `kd/docs/FINDINGS.md:77-85`, citing `run-crossgen/kd11/significance.json`.

## What I did
`audit/scripts/claims/F-04.py` reads the raw `tests[]` list and (a) reports the family shape,
(b) reads the two quoted tests, (c) **re-derives BH q-values over candidate sub-families** to
find which family reproduces 0.931 / 0.855 and "1 significant". It was run on the **git/laptop
copy** (4,032 tests) and, unchanged, on the **lab copy** (4,788 tests).

## Result — the 384-test family is recoverable, and the claim reproduces on it

The file's own note says *"BH within each block over every pooling × layer × probe ×
comparison"*. The git copy has **16 comparisons × 3 probes × 2 poolings × 21 layers × 2 blocks
= 4,032**. Restricting to the two layers the first run covered (**40 and 44**, per
`logs/kd_crossgen.log` run 1, 20:10–20:14) gives **16 × 3 × 2 × 2 × 2 = 384** tests — exactly
F-04's count — with BH applied per block, i.e. over 192 tests each.

Re-deriving BH over that family (git copy, block 9):

| quantity | F-04 says | re-derived on the 384/192-test family | in the file today (git, 4,032) | in the file today (lab, 4,788) |
|---|---:|---:|---:|---:|
| `axes − raw` diff | +0.015 | **+0.0147** | +0.0147 | +0.0147 |
| dataset 95% CI | [−0.170, +0.187] | **[−0.1701, +0.1872]** | same | same |
| q(`axes − raw`) | 0.931 | **0.9311** ✅ | 0.9630 | 0.9725 |
| `axes − datapca` diff | +0.026 | **+0.0264** | +0.0264 | +0.0264 |
| q(`axes − datapca`) | 0.855 | **0.8546** ✅ | 0.8958 | 0.9060 |
| significant after BH | 1 | **1** ✅ | 0 of 4,032 | 0 of 4,788 |

So **every number in F-04 reproduces**, but only once the original test family is
reconstructed. This is RF-13 in its purest form: the raw statistics (diff, CI, `dataset_p`)
survive every regeneration byte-for-byte; the BH q-values do not, because the family grew from
384 → 4,032 (21 layers) → 4,788 (21 layers + the three `axes_resid` comparisons). The stated q
and the "1 significant" **cannot be read from any file that exists today**.

Note the lab copy cannot reproduce it at all: with 19 comparisons its layers-40+44 family is
456 tests and block 9 gives q = 0.9727 / 0.8948. Only the **git copy's 16 comparisons** give
384 and 0.931 / 0.855.

## Two things the entry does not say, and one that is wrong

1. **The single significant test is not a persona-coordinates result.** It is
   `block 9, last pooling, L44, mms probe, random@2 − raw`, q = 0.0192, **diff = −0.2287** —
   i.e. the only thing that clears the bar is that a *random 2-d projection is worse than raw*.
   Read as "one comparison survived", F-04 is right; read as "one persona-axis result
   survived", it would be wrong.
2. **The quoted L40 numbers are the 10-dataset block, not the 11-dataset one.** `block '9'`
   has `pairs = 90` ⇒ 10 datasets (`sycophancy_mt` excluded); `block '10'` has `pairs = 110`
   ⇒ 11. F-04 says "in the 11-dataset paper16 run". The run does have 11 datasets, but the two
   numbers quoted come from the block that drops `sycophancy_mt` — and on the **full 11**
   the signs flip: `axes − raw = −0.0215` (q 0.9067) and `axes − datapca = −0.0243` (q 0.9163).
   So the favourable sign of "+0.015 / +0.026" is produced by the exclusion. This matters
   because F-13 shows `sycophancy_mt` is exactly the column that drags `axes` down.
3. The `block` labels are off by one in the kd11 store (block "9" = 10 datasets, block "10" =
   11), while in the root store they match the dataset count (block "9" = 9, "10" = 10) — an
   easy way to misread these files.

## Robustness
Not a layer claim, so no layer sweep applies to the quoted numbers themselves. But the
direction of the conclusion is stable: across the full current file **0 of 4,032 (git) and 0 of
4,788 (lab)** tests are flagged `significant_datasets`, in either block.

## Verdict — **HOLDS (on the reconstructed original family); the cited file no longer shows it**
Confidence **HIGH** for the arithmetic (every number re-derived from the raw per-test
statistics on two independent copies); the caveat is about provenance, not correctness.
Importance **HIGH** — this is the significance bar the whole project's headline numbers have to
clear, and the "11-dataset" wording plus the identity of the one significant test both need
fixing in the ledger.
