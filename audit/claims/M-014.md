## The claim, in one plain sentence
Re-judging the paper16 persona rollouts with `meta-llama/Llama-3.1-405B-Instruct` instead of
`meta-llama/Llama-3.1-70B-Instruct` — same rollouts, judge the only variable — gives **91.2 %
exact-score agreement** and moves the **score-3 rate**, which selects the rollouts that build the
persona vectors, by only **0.8 pp**.

## Evidence

  (25 files, 405B judge), both in the working tree and **both tracked in git on `asix`**.
- `run-paper16/responses/*.jsonl` (26 files).
- The judge identities come from code, not from the score files (which hold bare ints):
  `src/assistant_axis_ndif/run_judge_405b.ps1:44-50` passes
  `--responses_dir run-paper16\responses --output_dir run-paper16\scores_405b
  --judge_model meta-llama/Llama-3.1-405B-Instruct`, and `3_judge_ndif.py:261` defaults to
  `meta-llama/Llama-3.1-70B-Instruct`. So "same rollouts, judge the only variable" is
  **verified from the launch command**, not assumed.

## The one loose statement
Line 8 says "Re-judged **all 1,400** paper16 rollouts". `responses/` holds 1,400 records across 26
files, but only **1,350** were judged by either model: the 26th file is `default.jsonl` (50
rollouts, the anchor persona) and it has no score file in *either* store. That is by design:
`2_activations_ndif.py:20-21` says `"Kept" = judge score == 3 (--keep_scores), except 'default'
where all responses are used` — the anchor is never filtered, so it is never judged. The note's own
body is consistent ("1,231 of **1,350** comparable"), so this is loose phrasing, not a wrong
number.
